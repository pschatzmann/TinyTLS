Detailed Description

TLS 1.3 client session (RFC 8446): handshake, record layer and application data.

The session runs over a Transport and draws randomness from a Drbg. Every operation that would block returns Error::WantRead or Error::WantWrite, and the next call continues where the previous one stopped. This keeps the session usable from a single-threaded Arduino loop.

Supported: TLS 1.3, client role, the cipher suites TLS_AES_128_GCM_SHA256 and TLS_CHACHA20_POLY1305_SHA256, the X25519 key exchange, SNI, KeyUpdate, and the verification modes None, Optional and Required.

Not supported: HelloRetryRequest, client certificates, pre-shared keys, 0-RTT and session resumption.

Applications normally use TinyTLS, which owns the entropy, the DRBG and the configuration. Session is available for code that manages those parts itself.
